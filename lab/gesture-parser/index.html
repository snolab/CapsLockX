How the parse works

Three passes, no timers anywhere — the structure comes from edge order alone, which is the same thing the engine has to reason about.

PassWhat it does
1. treeEach key-down opens a node inside the currently-innermost open node; each key-up closes it. Containment falls out of the edge order, so a key pressed while another is held becomes its child.
2. collapseA node holding exactly one child collapses into a group when their two up-edges are adjacent in the log — nothing happened between them. That is precisely the rule that ] needs the whole group released; a partial release leaves the nesting intact instead. A child that has a body is demonstrably a hold — something was struck while it was down — so holding a and b and striking e gives (a->b)[ e ] for any keys at all, with no key table and no clock. Only the childless case is ambiguous: c↓ s↓ s↑ c↑ and space↓ 3↓ 3↑ space↑ are the same shape, so there the key roles break the tie.
2b. connectGroup members are joined with +. Whether your fingers happen to nest or cross on release is not something anyone controls, so that difference is noise in captured input — the same intended gesture would otherwise render two ways. Nothing is lost, because the trace line still records the exact edges: observation lives in the trace, the binding lives in the spec. Flip the connector button to -> to see the order as actually pressed; crossings still show + there, since a crossing is real evidence of symmetry.
3. renderEmpty body and closed → X.  · empty and still held → X[  · non-empty → X[ body ], or X[ body while the hold is still open. Body keys print bare, because inside a hold a bare name already means a tap.

Strict nesting turns pass 2 off, so you can see the raw press order the engine sees — useful for reproducing T1, where capslock[ alt[ space[ 1 ] ] ] fails to form a chord because prior_key is alt when Space arrives.

What this can and cannot see

It reads the browser's key events, not the hardware

  • clx is upstream of it. If clx is running, keys its hook suppresses never reach this page — hold Space and you may see nothing at all. That is itself informative: run it once with clx paused to see raw input, once with clx active to see what survives the hook.
  • CapsLock is unreliable in browsers. Several report it as a lock toggle rather than a physical press, so the key-up can arrive at the wrong moment or not at all. The toggle-fallback checkbox treats a second CapsLock down as an up. For a clean rollover measurement, substitute another key.
  • Some keys are stolen by the browser or the OS — F5, F12, Win, Alt+Tab. preventDefault catches most but not all.
  • Auto-repeat is tagged and excluded from the tree, matching the engine, which deduplicates repeats via held_keys.
Notation and semantics: chord-fn-row. Interpretations below the readout use the documented CLX map plus the proposed chord layer, so a chord + digit reads as an F-key even though nothing is implemented yet.
