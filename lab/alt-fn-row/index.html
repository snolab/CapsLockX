CLX + Alt + number row → F1–F12

Edge-case audit, blast radius on the existing hotkey layers, and a recommended implementation plan. Nothing implemented yet.

CapsLockX 2.0 · branch beta Rust core + Windows adapter 2026-09-04

Two findings dominate everything else

1. CLX+Alt+4 would close the focused window. The engine never suppresses a physical Alt, so an injected F4 lands on the app as Alt+F4. Same class: Alt+F1, and a bare Alt transition activating the menu bar/ribbon.

2. Alt pressed before Space never reaches CLX at all. clx_dn bypasses Space whenever any modifier is held, so the OS gets Alt+Space (window system menu) instead. Only "Space first, then Alt" works today, and only for the Space trigger — CapsLock is fine either order.

Trigger = CapsLock or Space (either, as today). The layer only exists while Alt is also held.

4Recommended solution

Strategy choice for Alt neutralisation

S1 — Suppress Alt at the hook recommended

While in FN mode (a trigger physically held), return Suppress for LAlt/RAlt down and up, but keep them in held_keys. The OS never sees Alt: no Alt+F4, no menu bar, no WM_SYSKEYDOWN, no IME language flip. Fixes D6's latent bug too.

S2 — Isolate at injection time fallback

Batch [Alt↑, Fn↓, Fn↑] in one SendInput. Simpler, but hits B2/B3 — the injected Alt↑ reads as a lone Alt tap and pops the menu bar. Needs the AHK "dummy Ctrl tap" trick to defuse, which is fragile. Keep only for platforms where hook suppression isn't available.

Why S1 is the right default

It is the only option that makes CLX+Alt+4 provably safe rather than probabilistically safe, and it retroactively fixes every existing CLX chord that misfires when Alt happens to be held (D6). The cost — no starting Alt+Tab while a trigger is held — is small and reversible.

Shape of the module

// core/src/modules/fn_row.rs
pub fn on_key_down(&self, key: KeyCode, mods: &Modifiers) -> bool {
    if !mods.alt { return false; }          // layer is Alt-gated
    let f = match key {
        KeyCode::D1 => KeyCode::F1,  /* … */  KeyCode::D9 => KeyCode::F9,
        KeyCode::D0 => KeyCode::F10,
        KeyCode::Minus => KeyCode::F11,
        KeyCode::Equal => KeyCode::F12,
        _ => return false,
    };
    // Alt is already suppressed at the hook (S1), so a plain tap is clean;
    // physically-held Shift/Ctrl/Win decorate it for free.
    self.platform.key_tap(f);
    true
}

5Decisions I need from you

#QuestionMy recommendation
Q1Sacrifice Alt+Space (Windows window system menu) so Alt-then-Space works, or keep the bypass and require Space-then-Alt order?Sacrifice it, behind a pref. An order-dependent hotkey is a bug report waiting to happen; the window menu is reachable from the title bar.
Q2CLX+Alt+Shift+3 — Shift+F3, or keep "move window to desktop 3"?Shift+F3. Alt is the layer selector and wins; move-window keeps its own unambiguous chord.
Q3Should F-keys auto-repeat while held?No — matches current digit behaviour and avoids F5-spam. Trivial to add later.
Q4Should the layer work in CLX-locked mode (bare Alt+1 after the CapsLock+Space chord)?Yes for the layer, no for Alt suppression — suppressing Alt globally while locked would be far too invasive.
Q5Does RAlt/AltGr participate?LAlt only, or alt && !ctrl. Costs nothing on your US layout and avoids breaking EU users.
Q6Bind by VK or by scancode?VK now, with a JIS 0xDE fallback for F12. Scancode is more correct but touches the injection path too; not worth it for a single-layout user today.
